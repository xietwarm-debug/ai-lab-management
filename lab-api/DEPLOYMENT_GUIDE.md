## 🔍 故障排查

### 问题1：导入错误

**错误信息**：
```
ModuleNotFoundError: No module named 'jieba'
```

**解决方法**：
```bash
pip install jieba==0.42.1 scikit-learn==1.3.2
```

### 问题2：查重率始终为0

**可能原因**：
1. 没有其他学生作业可供比对
2. 文件解析失败（PDF/图片等非文本格式）
3. 作业内容太短（<50字符）

**检查方法**：
查看API返回的 `limitations` 字段，会说明未进行查重的原因。

**示例响应**：
```json
{
  "suggestion": {
    "limitations": [
      "暂无其他同学作业可供比对，未进行查重检测。"
    ]
  }
}
```

### 问题3：前端不显示查重率

**检查步骤**：
1. 打开浏览器开发者工具
2. 查看Network标签中的API响应
3. 确认 `metrics.plagiarismRate` 字段存在
4. 检查前端代码是否正确更新

**常见原因**：
- 浏览器缓存未清除（Ctrl+F5强制刷新）
- 前端代码未重新编译
- HBuilderX需要重新运行项目

### 问题4：查重率异常高（>95%）

**可能情况**：
1. 两份作业确实完全相同（真抄袭）
2. 都引用了相同的标准答案模板
3. 文本太短导致偶然匹配

**处理建议**：
- 结合 `risks` 字段的详细说明
- 查看具体是哪位学生的作业相似度高
- 人工打开文件对比确认

## 📊 性能优化建议

### 1. 限制比对数量

当前系统限制比对最近5份作业，如需调整：

```python
# routes_teacher.py 第2570行左右
LIMIT 5  # 改为 LIMIT 10 可增加比对数量，但会降低性能
```

### 2. 缓存查重结果

如需避免重复计算，可以添加缓存：

```python
# 伪代码示例
cache_key = f"plagiarism:{task_id}:{student_name}"
cached_result = redis.get(cache_key)
if cached_result:
    return cached_result
```

### 3. 异步处理

对于批量分析，建议使用后台任务：

```python
# 使用Celery或其他任务队列
@celery.task
def batch_check_plagiarism(task_id):
    # 后台执行查重
    pass
```

## 🎯 答辩演示脚本

### 开场白（30秒）

> "各位老师好，今天我要展示的是我们系统的智能查重功能。在传统的作业批改中，教师很难发现学生之间的抄袭行为。我们的系统通过NLP算法自动检测作业相似度，帮助教师快速识别可疑作业。"

### 功能演示（2分钟）

1. **展示正常作业**
   > "首先，这是一份独立完成的作业，查重率只有18%，系统标记为绿色，表示原创度高。"

2. **展示抄袭作业**
   > "再看这份作业，查重率高达92%，系统用红色高亮显示，并提示'疑似抄袭'。这是因为该学生直接复制了另一位同学的作业。"

3. **展示批量分析**
   > "教师还可以一键对全班作业进行批量AI分析。系统会自动比对每个学生的作业，生成详细的分析报告。"

4. **展示技术原理**
   > "我们使用的是TF-IDF向量化和余弦相似度算法。简单来说，就是把文本转化为数学向量，然后计算它们之间的夹角。夹角越小，相似度越高。"

### 总结（30秒）

> "通过这个功能，教师可以在几秒钟内发现潜在的抄袭行为，大大提高了批改效率。同时，这也对学生起到了警示作用，维护了学术诚信。"
